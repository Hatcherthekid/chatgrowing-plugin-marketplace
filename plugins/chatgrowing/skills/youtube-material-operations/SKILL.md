# YouTube 素材运营

用于广告的素材上传并回读成功后，只把已确认的视频引用与版本交给当前 Gateway 的广告 Action 能力。素材发布和广告创建是两个独立结果；广告仍须单独准备并满足对应平台的确认门禁。

## 入口

仅列出可用频道时直接调用 `material_targets`，按返回权限列出全部可见频道，不要求用户先选一个频道。需要最近视频或综合任务状态时调用 `material_youtube_workspace`；需要选定频道执行操作时才要求选择目标。读取 YouTube 工作区，取得当前成员可用频道、授权版本、最近同步、视频、模板、上传任务、媒体操作及服务端建议。除非服务端明确返回需要补权，不重新发起 Google OAuth；企业频道授权由组织复用，成员只使用当前 ChatGrowing 登录和自身权限。

同一个 Google 身份可以连接多个频道；每个频道是独立 `target_id`，共享的 `authorization_group_id` 只说明它们属于同一外部身份组。执行面向单个频道的操作时，工作区返回多个频道且用户没有指定目标，才让用户选择频道；不得按名称、默认频道或列表顺序猜测。增加另一个频道是新增企业资源连接，不是成员重新登录 ChatGrowing；Google 仍会要求选择本次连接的具体 YouTube 频道。

只查看频道不触发同步。用户要求视频数据且工作区提示当前授权版本尚未同步时，启动该频道同步并通过返回的同步 ID 查询进度。新对话可先列出同步、上传、批量或媒体 Operation 找回原任务，不以相同内容创建替代任务。

## 工具不可用时的处理

先使用 Host 的工具发现能力查找本插件工具；安装了 Skill 不等于 MCP 已连接。只进行一次正式工具发现和一次适用的连接状态检查。正常业务查询不读取其他任务、聊天历史、钥匙串或 OAuth 凭据，不扫描用户配置，不通过网页搜索代替授权数据。

只在 Host 已提供 ChatGrowing Resource Bridge 时使用它，并严格遵守该桥声明的只读能力；不得猜测资源 URI 或把只读桥当作素材写入入口。正式工具与桥均不可用时，简短报告失败阶段及已观察错误，保留原任务，不循环让用户重装、重登或新建任务。

系统 curl 能访问服务、钥匙串存在记录，都不能证明当前 Host 已连接或身份有效。没有明确的 Host 权限拒绝证据，不归因于沙箱，也不建议开启“完全访问”。禁止提取 Host token 发直连请求、编写临时 Python/Node OAuth/PKCE 桥或另建素材登录。仅在正式远程客户端明确返回 `login_required` 时使用该 Host 的 ChatGrowing 连接流程；刷新失败须报告连接层错误，不能反复重连或读取原始凭据。免安装接入不要求用户安装本地连接器。

只有 `chatgrowing_material_local` 可调用时，说明本地文件助手已提供；它不证明远程 Gateway 已连接，也不代表 Google Ads、AppsFlyer 或 YouTube 平台操作可用。远程工具缺失时先报告“远程能力尚未进入当前任务”，不能据此判定企业未绑定、外部账号未授权或数据不存在。`auth_status: unknown` 也不能作为重新授权依据。以当前任务的原生启动状态及明确错误区分发现、连接、认证、初始化和工具登记；缺少对应证据的阶段保留未知，不拼接其他进程的网络探针作根因。

## 新增频道连接

新增频道使用 `material_youtube_connect` 及当前成员权限，不依赖本地文件助手或本地 Python。企业已有频道直接复用授权。没有可调用的正式连接工具时，明确说明 Agent 连接入口尚未提供；仅可引导至已确认存在的产品连接入口，不自行实现 OAuth，也不调用本地素材登录来替代。不得把缺少连接工具说成用户未授权。

## 任务选择

- 查看频道或最近视频：使用工作区或视频列表；精确对象使用视频详情。只把当前授权版本且未过期的观察写成可见事实。
- 上传新视频：先检查当前 Host 是否真正支持远程 `material_intake_receive` 的 `file` 参数，并只接收用户明确选定的文件。Host 不支持时，使用已正式发布的 ChatGrowing 网页上传入口让用户选择文件，再从服务端回读固定 `file_id` 与素材版本；如果网页入口尚未发布，应准确报告文件接收能力缺口，不宣称上传成功。选择频道模板或逐项补齐发布字段。使用 `material_distribution_batch_submission_preview` 核对固定文件、频道、可见性和发布字段；用户本轮指令已明确覆盖清单时，调用 `material_distribution_batch_submit` 一次提交，不重复请求确认。仅在用户意图或关键字段不明确时追问。审核是可选意见，不代替发布指令。
- 复制已有素材：从源素材创建独立变体，再修改新变体的发布字段。复制不继承旧审核；封面和字幕等专属附件需要重新选择。
- 修改已发布视频：先以当前视频绑定的素材创建新版本或变体，保存需要修改的发布字段，再预览精确视频操作并请求用户确认。删除先预览精确频道、视频 ID 和标题；用户已明确要求删除该对象时，该指令即为确认，可调用 `material_video_operation_confirm`，无需再等待 Host 弹窗。目标不明确或用户仅要求查看时不得删除。删除不可恢复，结果未知时只对账原操作，不换键重发。
- 批量发布：固定源版本、频道和配置清单，`prepare` 后读取 `submission_preview`；用户指令覆盖每一项时，以预览返回的 `manifest_digest` 和稳定 `request_key` 调用一次 `submit`。内部保存草稿不再要求用户操作；逐项结果是事实，批次完成状态不能替代逐项成功、失败或未知。不得因本地进程重启或工具调用取消而换键新建发布批次。
- 模板：只保存稳定默认值。儿童声明、合成媒体声明、绝对发布时间以及具体封面/字幕由当前任务提供证据或用户决定，不能从模板猜测。

## 恢复与停止条件

平台已接收但结果未知时，只查询或 reconcile 原任务；不得换幂等键重传。授权版本变化后先同步当前授权版本，再进行修改或删除。发现权限撤回、目标变更、确认过期、源文件变化或审核快照变化时停止依赖该证据的写入，并使用服务端返回的安全下一步。

所有外部写入保留任务、素材版本、确认、平台回执和回读证据。向用户报告已确认、处理中、未知和失败，不把排队、HTTP 接收或服务存活当作 YouTube 已完成。

## 免安装文件接收与发布

通过正式远程 MCP 完成 ChatGrowing 连接和频道权限检查。文件字节只走当前 Host 已验证可用的 `material_intake_receive` 文件参数，或用户在已发布 ChatGrowing 网页中主动选择文件；不要从模型文本参数发送本地路径、视频字节或 Host token。不可把“工具声明有 file 参数”直接当作当前 Host 已能传文件。

单文件和批量文件均以服务端返回的 `ready`、固定 `file_id` 与素材版本建立发布清单。网页上传和 Agent 任务必须核对同一组织、用户可用范围与任务身份；没有可核对的交接能力时，不猜测素材对应关系。接收 `ready` 只证明 ChatGrowing 已保存并检查原件，之后仍须执行预览、一次提交和 YouTube 结果回读。Host 文件参数和网页入口都不可用时，准确报告接收能力缺口；不退回历史本地 helper、安装器或运行环境下载流程。
