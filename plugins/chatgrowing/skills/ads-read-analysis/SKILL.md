# Ads · 自由分析

## 入口

普通查数使用 `ads_schema` 和 `ads_sql`：需要了解表时查 schema，已知表结构时直接写 SELECT / WITH。无需先查 capability、跑健康扫描、发布 Artifact、保存结果或获取续查句柄。权限由服务端的只读连接和业务视图执行。

只有账户权限、连接配置或独立操作能力的问题才调用 `ads_capability_context`。显式 AF App 授权允许查该 App 的 AF 全媒体数据；媒体账户授权只允许对应账户。不得从 App 名称或 facet 推导权限。

Host 未披露工具但提供正式 Resource Bridge 时，可读取 `ads-contract://host-tool-fallback-v1` 按合同恢复同一只读能力。

## 工具不可用时的处理

先使用 Host 的工具发现能力查找本插件工具；安装了 Skill 不等于 MCP 已连接。只进行一次正式工具发现和一次适用的连接状态检查。正常业务查询不读取其他任务、聊天历史、钥匙串或 OAuth 凭据，不扫描用户配置，不通过网页搜索代替授权数据。

只在 Host 已提供 ChatGrowing Resource Bridge 时使用它，并严格遵守该桥声明的只读能力；不得猜测资源 URI 或把只读桥当作素材写入入口。正式工具与桥均不可用时，简短报告失败阶段及已观察错误，保留原任务，不循环让用户重装、重登或新建任务。

系统 curl 能访问服务、钥匙串存在记录，都不能证明当前 Host 已连接或身份有效。没有明确的 Host 权限拒绝证据，不归因于沙箱，也不建议开启“完全访问”。禁止提取 Host token 发直连请求、编写临时 Python/Node OAuth/PKCE 桥或另建素材登录。仅在正式客户端明确要求重新认证时，按现有单一 ChatGrowing 登录流程恢复。

## 工作方式

1. 根据问题确定日期、对象、指标和比较范围。表结构未知时，用 `ads_schema` 取得相关表字段、粒度和指标定义；已有 schema 可以复用。
2. 在 `ads_sql` 中执行 SQL 完成筛选、分组、关联、比较和排序，再解释返回结果。大数据先在数据库聚合；不要把明细全部搬到上下文。`truncated=true` 时调整 SQL，不能把截断行当完整数据。
3. 按问题与已授权来源选择口径：原生媒体转化、配置、变更和维度直接查媒体表，不要求 AF。明确需要 AF 归因或关联指标时再查 AF/fact；其它归因来源未支持时说明该来源缺口，保留已有媒体结论。使用原生 ID 关联，禁止名称 join。
4. 按所选表 Schema 区分原生粒度、日期、归因窗口、次数/人数和币种；D0/D1/D3 只适用于对应 AF cohort 合同。比率按正式定义聚合分子分母后计算，不能求和或平均行比率。已知 Campaign 但缺广告组的 AF-only 行仍可进入 Campaign 汇总；真实缺少日期/模块覆盖另行说明。
5. 追问继续修改 SQL；无需发布结果集、续查 token 或 Workspace。先答已查到的业务结论，只有影响结论的未解释缺口才按需查同步回执。

## 正常业务情况与缺失

- Campaign 上期中途开始投放，少几天属于实际投放时长；可说明对环比的影响，不能直接称为采集缺口。
- 已知未配置、未投放的渠道，没有花费或曝光点击是正常情况，不自动启动排障。单凭缺行仍不能证明从未投放。
- NULL 保持未知；真实 0 保持 0。单个缺失字段只影响相关指标，不阻断其它结果。
- 不把“覆盖不完整”当泛化结论。确有影响时说明具体字段、日期、对象及影响；无需每次查询都展开健康审计。
- 普通分析不保存 Artifact。用户明确要保存、导出或正式报告时，由对应消费者保存所需结果；Agent 对话记忆不替代数据库事实。

## 计数口径

- 用户明确说事件次数、event count 或 PV 时使用 `total_events`；明确说人数、用户数或 UV 时使用 `unique_users`。
- 按用户问题、所选来源及 Schema 选择次数或人数。未明确口径时标明本次使用的原生定义；可并列时分别展示，不将 AF UV 或行业事件作为跨企业默认。
- AF cohort/actual 及多日去重能力以所选表 Schema 为准；不能将 actual/activity 每日 UV 之和称为累计去重漏斗。媒体原生转化不套用 AF 的窗口或事件映射。
- 多日或多对象 UV 相加必须称为 `Daily UV Sum / 每日 UV 之和`，并明确说明同一用户跨日可能重复计算，它不是整个日期范围内真正去重的 UV。不得简称为 UV、区间独立用户数或去重用户数。

## 边界

- 模型能看到的数据由权限裁剪决定，模型本身不决定权限。
- 正式指标由服务端计算；不自行重算或用名称猜映射。
- 原生版位、国家、设备问题读取对应媒体 dimension 表；AF 关联指标读取正式 placement fact。媒体 action 名称保留原生含义，不能自行升级成企业业务事件映射。
- 未知、未采集、无权限、同步失败、不可比和真实零必须区分。
- 证据不足时明确 `cannot_judge`；不执行广告平台写入或外部发送。
